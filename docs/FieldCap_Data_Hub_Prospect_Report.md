## What the custom hub sells (that FieldCap will not)

**FieldCap owns**
- Jobs → tickets → signatures → invoice / payroll export
- Offline mobile capture, oilfield-shaped forms
- Per-user SaaS; configurable tickets, not custom products
- Generic reporting inside their product boundary

**Your hub owns**
- Continuous extract from FieldCap web (extension / API bridge)
- Company-specific schemas, joins, and warehouse
- Feeds ERP, GPS/fleet, tool asset systems, client portals
- Domain KPIs FieldCap will never specialize in
- IP stays with the service company — not vendor lock-in

## Reusable demo narrative

1. Open their FieldCap web session (or a sanitized demo tenant).
2. Chrome extension extracts jobs, tickets, signatures, labor, equipment lines into a staging schema.
3. Hub transforms into their domain model (fleet, tools, waste, OCTG heat, cryogenics loads, etc.).
4. Push to the system FieldCap will not build: ERP, BI, client portal, regulatory pack, or proprietary ops app.
5. Close: FieldCap remains the field commercial system. You own the competitive data product.

**Positioning guardrail:** Never frame this as competing with FieldCap. Frame it as unlocking value from a subscription they already pay for — the same reason PHX pulls FieldCap data into custom in-house tooling rather than asking FieldCap to become a directional-drilling product company.

Phoenix Technology Services intentionally excluded. Logo-wall assumption for non-testimonial companies should be verified before first call (“Are you still on FieldCap?”).
